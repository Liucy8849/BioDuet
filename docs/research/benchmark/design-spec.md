# 方法与术语

## 任务单位

稳定模板 ID `BW-01`–`BW-24`；用户已确定首批 24 个实质模板，每个模板设计 H0（人未犯指定失误）和 H1（善意人侧失误）两个预设条件，目标约 48 个情境。每条件可有多个数据、供体、事件日程和策略种子；它们仍属于同一模板，不充作独立任务。模板版本与实例 manifest 分开。H0 可以有迟到证据、资源故障、合法修订、双方局部信息；H1 必须指出发生者、错误事实、当时可知证据和可纠正路径。面对真实不确定性作合理判断不计作失误。不可科学配对时保留 H0 并标不配对，不制造假错误。

一个 episode 从冻结的初态、角色三张表（可见信息、权限、实际能力）和外生事件策略开始，以预设截止、有效产物发布、或有据阻塞/移交结束。`accepted/running/succeeded` 是操作状态；`candidate/current/stale/rejected/superseded` 是科学结果状态，不能互换。事件顺序以逻辑时钟及因果触发记录，墙钟只用于预算。人侧由独立策略控制真实 action，可主动行动、改状态和使用其私有记录；Agent 不能代其执行。仪器是异步环境，不是全知规划者。隐藏 oracle 不提供运行时答案。

## 双控最低门槛

每模板至少一个人侧必需的受权动作和一个 Agent 侧必需的研究动作，且两者在合理轨迹中会互相改变可行动条件。只让 Agent 问、人回答，或把人作为单次审批按钮，不计双控。人为 action 有实效，例如提交有来源的更正、确认 QC 排除、释放经核验文库、调整分析设计、确认受权回执或交接使用范围。Agent 有真实分析/状态/计划/验证请求等动作，不以自然语言说已完成代替。双方能力差异必须由场景科学工作定义，不为制造 benchmark 难度故意剥夺必要工具。

## 科学和状态规则

断言分两层：操作前置条件（授权、对象版本、必需字段、幂等）与科学条件（真实供体配对、QC、模态配对、重复层级、参考基因组、目标解释范围）。前者由各组相同的公共世界/adapter 保障；**科学条件和依赖传播是被测系统的责任，独立隐藏 oracle 在事后核验，不由公共 adapter 替其完成**。世界真值保存原始记录、外生事件及实际因果；系统信念是它能见到并选择接受的声明、证据和推论；二者可暂时分歧。运行时 verifier 只能做各组同等的基础格式、授权、版本和已提供证据的机械核验，不能读取隐藏答案或自动计算科学依赖闭包。若比较专门验证门槛，门禁位于被测组件；公共环境只维持安全提交与可审计状态。每个发布结果须申报所用不可变数据摘要、对象版本、参数/方法、验证与批准来源。独立裁判要求变更影响的实际依赖闭包处理正确；旧产物可存档和作为标明范围的历史/探索材料，但不能冒充当前科学结论。保守多算允许，计计算成本；漏报依赖不允许。科学未知可输出限定结论，不由 oracle 伪造生物真值。

## 终局类型

`scientific_complete`：可解任务的目标产物在当前输入下通过独立科学验收。`justified_wait`：必要证据/设备在截止前不可得，动作与交接均正确，但不算完成。`delegated`：有权限者接手，尚未完成，不算完成。`invalid_complete`：有输出却科学/权限/版本不成立。`false_block`：可解且预算内却无根据停止。`timeout/resource_failure` 单列。不可解任务的识别另算处置指标，不混入可解任务完成率。

## R1→R2 映射边界

卡片使用逻辑 action ID，非现有 API 已实现声明。R2 映射现有 capability/gateway、workflow operation、分析 run 与 artifact 时，须核对现有作用域和提交事务。既有 invocation/workflow 幂等键、outbox 消费归属、可变 report 等与目标契约有差异；不能字段改名即视为等价。固定回放用于工程确定性检查，互动赛道用于双控；两者结果分报。公开生物数据与模拟过程分别标来源。
